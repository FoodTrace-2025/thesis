# Story 2.4: Company Reject API

## Status

**Done**

## Story

**As a** platform administrator,
**I want** to reject pending companies via an API endpoint with a mandatory reason,
**so that** I can decline unsuitable B2B partners while maintaining an audit trail of the decision.

## Acceptance Criteria

1. POST /api/admin/companies/:id/reject endpoint created and functional
2. Only companies with status PENDING can be rejected (returns 409 for APPROVED/REJECTED)
3. Request body requires mandatory `reason` field (string, 1-500 characters)
4. Company updated atomically: status=REJECTED, rejectionReason
5. AuditLog entry created with action "REJECT_COMPANY" and reason in details
6. Returns 404 for non-existent company ID
7. Returns 400 for missing or invalid reason
8. Rejection is final (no re-approval allowed - per POC simplicity decision)
9. Endpoint accessible without authentication (auth added in Story 2.5)

### Request/Response Format

**POST /api/admin/companies/:id/reject**

Request:
```json
{
  "reason": "Incomplete business documentation"
}
```

Success Response (200 OK):
```json
{
  "success": true,
  "company": {
    "id": "clxyz123...",
    "name": "Hirsimaki Farm Ltd",
    "email": "contact@hirsimakifarm.fi",
    "domain": "hirsimakifarm.fi",
    "type": "PRODUCER",
    "status": "REJECTED",
    "rejectionReason": "Incomplete business documentation",
    "createdAt": "2025-11-27T12:00:00.000Z"
  }
}
```

Error Response (400 Bad Request - Missing reason):
```json
{
  "error": "Validation failed",
  "code": "VALIDATION_ERROR",
  "details": [
    { "field": "reason", "message": "Rejection reason is required" }
  ]
}
```

Error Response (404 Not Found):
```json
{
  "error": "Company not found",
  "code": "NOT_FOUND"
}
```

Error Response (409 Conflict):
```json
{
  "error": "Company is already approved",
  "code": "CONFLICT_ERROR"
}
```

### AuditLog Entry

```typescript
await tx.auditLog.create({
  data: {
    action: 'REJECT_COMPANY',
    companyId: company.id,
    userId: null, // Auth not implemented yet - see Story 2.5
    details: {
      reason: reason,
    },
  },
});
```

### Error Handling

| Error | Status | Response |
|-------|--------|----------|
| Missing reason | 400 | `{ error: "Validation failed", code: "VALIDATION_ERROR", details: [...] }` |
| Reason too long | 400 | `{ error: "Validation failed", code: "VALIDATION_ERROR", details: [...] }` |
| Company not found | 404 | `{ error: "Company not found", code: "NOT_FOUND" }` |
| Already approved | 409 | `{ error: "Company is already approved", code: "CONFLICT_ERROR" }` |
| Already rejected | 409 | `{ error: "Company is already rejected", code: "CONFLICT_ERROR" }` |

### Design Decision: Rejection is Final

Per Session 34 discussion, rejection is final for POC simplicity:
- No REJECTED → APPROVED transition allowed
- If rejection was a mistake, delete company and recreate
- Future enhancement: Could add re-approval workflow if needed

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Accidental rejection | Clear error messages, can recreate company if needed |
| Missing audit trail | Mandatory reason field ensures documented decisions |
| Empty reason bypass | Zod validation enforces min 1 character |
