# Story 7.16: SHIPPED Action - Recipient Selection

## Status

**Complete** (2025-12-05)

## Story

**As a** distributor,
**I want** to select which company receives my shipment when marking a product as SHIPPED,
**so that** the recipient company knows the product is coming to them.

## Background

Currently, when a distributor marks a product as SHIPPED, the system only records that the product left. There's no tracking of where it's going. This makes the receiving workflow awkward - recipients must search by product ID.

This story adds the foundation: capturing recipient info when shipping. Story 7.17 will use this data to show incoming shipments to recipients.

**Design Decision (Research-Based):** Per [MDPI research on traceability systems](https://www.mdpi.com/2076-3417/14/23/11078), `recipientCompanyId` is stored in the database only (not blockchain). Blockchain records the immutable SHIPPED event; recipient info is operational metadata.

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Storage | Database only | Operational metadata, not core traceability |
| Company filter | All approved D+R | Flexibility for demo scenarios |
| Selector visibility | SHIPPED action only | UX - don't show irrelevant field |

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Company API security | Require authentication, only return approved companies |
| Form complexity | Conditional rendering - only show when needed |
| Empty company list | Show helpful message if no companies approved |
