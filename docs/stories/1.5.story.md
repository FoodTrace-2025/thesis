### Reference Information

**From Epic 1 (docs/prd/epic-1-project-setup.md):**

- WALLET_ENCRYPTION_KEY is used to encrypt custodial wallet private keys
- Custodial wallets are created for retailers who don't have their own wallets
- The key must be 256-bit (32 bytes = 64 hex characters) for AES-256 encryption

**Required Environment Variable Format:**

```bash
# Wallet Encryption (Generated)
WALLET_ENCRYPTION_KEY="YOUR_64_CHAR_HEX_KEY"
```

**Generation Command:**

```bash
openssl rand -hex 32
# Output example: 7f8a9b2c3d4e5f6071829384a5b6c7d8e9f0a1b2c3d4e5f60718293a4b5c6d7e
```

**Why Encryption Key?**

- **Custodial Wallets:** FoodTrace creates wallets for retailers without crypto experience
- **Security:** Private keys stored in database must be encrypted at rest
- **Compliance:** Standard security practice for handling sensitive cryptographic material
- **Recovery:** Same key needed to decrypt wallets - NEVER lose this key

### Risks & Mitigations

| Risk                          | Mitigation                                            |
| ----------------------------- | ----------------------------------------------------- |
| Key lost                      | Backup in password manager immediately after generation |
| Key exposed in Git            | .env.local already in .gitignore                      |
| Weak key generated            | Use openssl (cryptographically secure PRNG)           |
| Team member loses key         | All members have copy + password manager backup       |

### Testing

**Manual Verification:**

- Key length: exactly 64 characters
- Key format: only hexadecimal (0-9, a-f)
- Key stored in .env.local

**Validation Command:**

```bash
# Check key length
echo -n "YOUR_KEY_HERE" | wc -c
# Should output: 64

# Check hex format
echo "YOUR_KEY_HERE" | grep -E '^[0-9a-f]{64}$'
# Should output the key if valid
```
