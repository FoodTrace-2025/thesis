### Critical Dependency Information

**IMPORTANT:** This story creates the database foundation but does NOT implement:
- Wallet encryption (requires Story 3.1 - Epic 3 Tier 1)
- NextAuth.js authentication (Story 2.2+)
- Company approval flow (Story 2.3+ after Epic 3.1)

The wallet fields (encryptedPrivateKey, walletAddress) are created as NULLABLE because they will be populated later when a company is APPROVED, which requires the wallet encryption utility from Epic 3 Tier 1.

### Prisma Schema Reference

Based on `docs/architecture/database-schema.md` and `docs/prd/epic-2-company-user-management.md`:

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

model Company {
  id                  String    @id @default(cuid())
  name                String
  email               String    @unique
  domain              String    // e.g., "hirsimakifarm.fi"
  status              String    @default("PENDING") // PENDING | APPROVED | REJECTED
  type                String    // PRODUCER | DISTRIBUTOR | RETAILER
  rejectionReason     String?   // Reason if rejected

  // Wallet fields - populated on approval (requires Epic 3.1)
  encryptedPrivateKey String?   // AES-256-GCM encrypted (Epic 3)
  walletAddress       String?   @unique // Ethereum address (0x...)

  createdAt           DateTime  @default(now())
  updatedAt           DateTime  @updatedAt
  approvedAt          DateTime?

  users               User[]
  auditLogs           AuditLog[]

  @@index([status])
}

model User {
  id           String    @id @default(cuid())
  email        String    @unique
  passwordHash String    // bcrypt hash
  name         String
  role         String    // PLATFORM_ADMIN | COMPANY_ADMIN | PRODUCER | DISTRIBUTOR | RETAILER

  companyId    String?   // Nullable for PLATFORM_ADMIN
  company      Company?  @relation(fields: [companyId], references: [id], onDelete: Cascade)

  createdAt    DateTime  @default(now())

  auditLogs    AuditLog[]

  @@index([companyId])
}

model AuditLog {
  id        String   @id @default(cuid())
  action    String   // CREATE_COMPANY | APPROVE_COMPANY | REJECT_COMPANY | CREATE_USER | CREATE_WALLET | etc.
  details   Json?    // Additional context (walletAddress, productId, etc.)

  userId    String?
  user      User?    @relation(fields: [userId], references: [id])

  companyId String?
  company   Company? @relation(fields: [companyId], references: [id])

  timestamp DateTime @default(now())

  @@index([companyId, timestamp])
  @@index([userId, timestamp])
  @@index([action, timestamp])
}
```

### Password Hashing Note

The `passwordHash` field will store bcrypt-hashed passwords. The hashing implementation will be in Story 2.2 (User creation API). Based on best practices research:
- Use bcryptjs package (pure JS, works in all environments)
- Use 10-12 rounds of hashing (balance security/performance)
- Never store plain text passwords

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Schema conflicts with existing tables | Using `db push` for development (non-destructive) |
| Missing DATABASE_URL | Verified in Story 1.1 and 1.6 |
| Wrong connection string (port 5432 vs 6543) | Use DIRECT_URL for migrations, DATABASE_URL for queries |
| Prisma Client not generated | Always run `npx prisma generate` after schema changes |
