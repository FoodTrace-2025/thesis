# Story 7.18: QUALITY_FAIL Action + Quarantine Flag

## Status

**Complete** (Implemented and tested 2025-12-28)

## Story

**As a** distributor or retailer,
**I want** to record pass/fail results when performing a quality check,
**so that** failed products are flagged as quarantined and the rejection is immutably recorded on blockchain.

## Background

Currently, the system has QUALITY_CHECK as a trace action, but there's no way to indicate pass vs fail. When a product fails inspection (e.g., temperature breach, spoilage), the distributor/retailer can only record notes—the product remains in "In Custody" alongside sellable products.

Per [SG Systems Global best practices](https://sgsystemsglobal.com/guides/inventory-quarantine-system/): "If quarantine doesn't stop a pick, it isn't quarantine—it's décor." Rejected products MUST be visually separated from active inventory.

**UX Design (Team Decision):** When user selects "Quality Check" from action dropdown, a secondary "Result" field appears with Pass/Fail radio buttons. This follows [NN/g guidelines](https://www.nngroup.com/articles/checkboxes-design-guidelines/) for mutually exclusive options.

This story adds:
1. Pass/Fail result selection when "Quality Check" is selected (radio buttons)
2. `QUALITY_FAIL` as a new backend trace action (sent when Fail is selected)
3. `isQuarantined` flag on Product model
4. Quarantined products filtered OUT of "In Custody" tab (owner=me excludes quarantined)
5. New `quarantined=me` API filter for fetching quarantined products

**Note:** Dashboard UI for quarantined products is in Story 7.19.

## Acceptance Criteria

### Schema Changes
1. Product model extended with `isQuarantined: Boolean @default(false)` field
2. Migration runs without data loss
3. Existing products default to `isQuarantined = false`

### Trace API Enhancement
4. QUALITY_FAIL added to valid trace actions
5. Recording QUALITY_FAIL sets `product.isQuarantined = true`
6. QUALITY_FAIL recorded on blockchain (same flow as other actions)
7. Audit log includes `isQuarantined: true` flag

### Products API Enhancement
8. New `/api/products?quarantined=me` endpoint returns quarantined products
9. Existing `/api/products?owner=me` excludes quarantined products (isQuarantined = false)
10. Mutual exclusivity validation: quarantined cannot combine with other filters

### Frontend Form Enhancement (UX - Teammate's Design)
11. When "Quality Check" is selected from Action dropdown, "Result" field appears
12. Result field shows radio buttons: Pass / Fail
13. Result is required when Quality Check is selected (validation)
14. Pass → sends `action: 'QUALITY_CHECK'` to backend (existing behavior)
15. Fail → sends `action: 'QUALITY_FAIL'` to backend (new action)
16. Result field hidden for all other actions (RECEIVED, SHIPPED, etc.)

### Timeline Enhancement
17. QUALITY_FAIL displayed with red/error color in trace timeline
18. QUALITY_FAIL label shows "Quality Fail" (distinct from "Quality Check")

### Edge Cases
19. Products quarantined before Story 7.18 not affected (migration safe)
20. Quarantined products still visible in "Product History" tab (for audit trail)
21. Consumer trace view shows QUALITY_FAIL in timeline (transparency)

**Dashboard UI (Story 7.19):** Quarantined Products section on distributor/retailer dashboards.

{action === 'QUALITY_CHECK' && (
  <FormControl isRequired isInvalid={!!errors.result}>
    <FormLabel color="brand.dark">Result</FormLabel>
    <RadioGroup value={result} onChange={(val) => setResult(val as 'PASS' | 'FAIL')}>
      <HStack spacing={6}>

// In handleSubmit - map result to action
const finalAction = action === 'QUALITY_CHECK' && result === 'FAIL'
  ? 'QUALITY_FAIL'
  : action;

// Validation: require result when QUALITY_CHECK selected
if (action === 'QUALITY_CHECK' && !result) {
  setErrors((prev) => ({ ...prev, result: 'Please select Pass or Fail' }));
  return;

### UX Flow

**Current (Before Story 7.18):**
```
Action dropdown: [RECEIVED, QUALITY_CHECK, SHIPPED, ...]
                         ↓
              Records QUALITY_CHECK (no pass/fail)
```

**After Story 7.18:**
```
Action dropdown: [RECEIVED, QUALITY_CHECK, SHIPPED, ...]
                         ↓
            User selects "Quality Check"
                         ↓
        Result field appears: (•) Pass  ( ) Fail
                         ↓
           Pass → sends QUALITY_CHECK to backend
           Fail → sends QUALITY_FAIL to backend → sets isQuarantined = true
                         ↓
            Failed product moves to "Quarantined Products" section
```

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Two actions vs result field on TraceRecord | Two actions (QUALITY_CHECK, QUALITY_FAIL) | Simpler, no TraceRecord schema change |
| Result field visibility | Conditional (only for Quality Check) | Same pattern as Story 7.16 "Ship to" |
| Result selection method | Radio buttons | Per NN/g: best for mutually exclusive options |
| Disposition actions | Not included (Future Work) | POC scope - display only |
| Producer notification | Not included | Larger feature (like Epic 6 email) |

### Future Work (Out of Scope)

Per [Dynamics 365 best practices](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/quality-management-processes):
- Disposition actions: Return to Sender, Mark as Disposed, Rework
- Producer notification when their product is quarantined
- Quarantine reversal (if re-inspection passes)
- Disposition audit trail

These are documented for thesis Chapter 8 (Future Work).

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| User forgets to select Pass/Fail | Required field validation |
| Quarantined products lost | Still visible in Product History tab (audit trail) |
| Consumer confusion | Timeline clearly shows "Quality Fail" with red styling |
| Breaking existing owner=me | Default isQuarantined = false, migration safe |
